# ADR 0004: Stateless PsychoPy Visual Rendering Pipeline

## Status
Accepted

## Date
2025-02-28

## Context
High-precision visual stimulus generation (e.g. multi-screen looming discs, sinusoidal gratings, optic flow starfields) requires hardware-accelerated OpenGL rendering, sub-millisecond vsync synchronization, and precise display timing. Embedding trial state machines, timing logic, or business rules into the rendering engine leads to high coupling and makes paradigms difficult to extend or test.

## Decision
Separate visual presentation from trial state machines via `CoreRenderer` (`src/core/render.py`):
- `CoreRenderer` is backed by PsychoPy `visual.Window`.
- Strict statelessness: `CoreRenderer` accepts declarative command dictionaries (`Circle`, `Rect`, `GratingStim`, `ElementArrayStim`) generated by paradigm state machines and applies them directly to visual objects.
- `CoreRenderer` contains zero trial state logic, zero time calculations, and zero hardware trigger logic.
- Paradigms inherit `BaseParadigm` (`src/models/paradigm.py`) and generate declarative draw commands in `process_frame()` and `get_idle_frame()`.

## Consequences
### Positive
- Paradigms can be unit tested without initializing OpenGL or display hardware.
- Core rendering code remains immutable and paradigm-agnostic (`src/core/BOUNDARY.md`).
- Rendering backend can be tested or swapped independently.

### Negative / Trade-offs
- Command dict protocol must be strictly observed by all paradigms.
